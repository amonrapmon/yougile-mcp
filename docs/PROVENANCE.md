### Distribution-rights investigation (2026-11-14)

The official [REST API guide](https://docs.yougile.com/docs/admin-guide-linux/api/)
and [API reference](https://ru.yougile.com/api-v2#/) describe how to use the
API, but the pages inspected do not state redistribution terms for the raw
OpenAPI JSON. The public [software license offer](https://ru.yougile.com/media/docs/offer.pdf)
addresses YouGile programs and does not explicitly grant rights to redistribute
this API schema. No explicit permission for that file was found. This is not a
conclusion that redistribution is either permitted or prohibited. The owner
has directed keeping this official snapshot in the development PR with its
source, hash, attribution and `license unknown` status. This is not a legal
permission finding and grants no rights to reuse code from other repositories.
Revisit distribution rights before release; escalate any rightsholder request
to the owner for a separate decision. PR #10 remains Draft for final review.

The coverage matrix is generated by `scripts/generate_openapi_catalog.py`.
All 72 operations now have operation-specific MockTransport coverage and are
`mock_tested`; none is marked `live_verified`. The matrix records five
`curl_observed` operations separately from Python-client live verification.
The sanitized manual evidence is in
`docs/verification/yougile-live-2026-11-14.md`; curl observations do not prove
the Python SDK called the live service.

Compatibility overlay `2026-11-14.1` is bound to the pinned OpenAPI SHA-256
`9452cba3571607848de77fc12e68104cb454e403c35c7a6b97521ea6e0d1d406` and is
implemented in `src/yougile_mcp/api/spec.py`. It leaves the vendor JSON and
source checksum untouched. The overlay maps both company operations to the
no-ID `/api-v2/companies` route, allows the curl-observed `deleted: null`
company response, validates webhook filter `name`/`value` as strings and the
search response as an array, removes the malformed multipart schema ref, and
accepts the observed upload response status 201 with the existing
`FileUploadDto` schema.

Only the owner-run curl GET verified the company route. Company PUT is
implemented against the canonical no-ID path and pinned `UpdateCompanyDto`,
with positive and negative mock contracts; no real company update was made.
The webhook string overlay follows the observed `title` filter; other filter
variants and webhook delivery remain unverified. Upload accepts bytes only,
uses multipart field `file`, defaults to a 10 MiB maximum and `text/plain`
allowlist, and supports constructor-level size/MIME policy configuration.
These upload restrictions are local policy, not vendor limits. Upload writes
are not retried after uncertain outcomes.

## Requirements before importing code

Record source URL, immutable commit SHA, owner, license, copyright notices,
relevant tests and the rationale for reuse. Update NOTICE.

If an upstream does not provide an explicit license or permission, do
not use its source implementation. A public GitHub repository is not
in itself a copyright license. Resolve PR #5 licensing in
https://linear.app/amonrapmon/issue/GEN-211.
